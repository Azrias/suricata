# Domain docs

Use a single-context layout: root `GLOSSARY.md` and `docs/adr/`.

Before exploring, read the glossary and relevant ADRs when present.
Proceed normally when absent; create them only as concepts or decisions
are resolved.

Use glossary terminology in issues, proposals, tests, and code discussion.
Note genuine terminology gaps for domain modeling. Explicitly flag conflicts
with existing ADRs instead of silently overriding their decisions.
